# Team Kazakhstan — справочник сотрудников группы компаний

Внутренняя веб-страница: сотрудники Algoritmi, Green Spark и других компаний
группы, их команды, должности, текущие задачи, языки и контакты. Открывается
на телефоне по короткой ссылке, установка приложения не нужна (нужен только
Tailscale, см. раздел 8). Интерфейс на английском (по умолчанию) и русском.

Эта инструкция — для установки на Synology через **Планировщик задач**
(Task Scheduler) и **Tailscale**, как устроены уже работающие сервисы.
Docker Compose и интерфейс Container Manager для этого не нужны.

## 1. Как устроено

```
Телефон / ноутбук с Tailscale
   │  https://team.<tailnet>.ts.net   (сертификат выдаёт Tailscale)
   ▼
контейнер teamkz-tailscale   — отдельная машина «team» в tailnet,
   │                            Tailscale Serve: HTTPS 443 → 127.0.0.1:8080
   ▼                            Funnel выключен: из интернета не виден
контейнер teamkz-app         — Node.js 24 + веб-интерфейс, без root,
   │                            read-only, без capabilities
   ▼
/volume1/docker/team-kz-data — база SQLite, фотографии, состояние Tailscale
/volume1/docker/team-kz-backups — архивы резервных копий
```

* Приложение и Tailscale-контейнер делят одну сетевую среду: приложение
  доверяет заголовкам прокси только от 127.0.0.1 (Tailscale Serve).
* Tailscale работает в userspace-режиме со своим состоянием: **Tailscale
  самого NAS, его Funnel и другие машины не затрагиваются**.
* Порт на NAS — только `127.0.0.1:8095` (для проверок с самого NAS);
  из сети и из интернета он не виден. Можно убрать совсем (`HTTP_BIND=`).
* Скрипты используют только команды `docker` (Docker Engine 20.10+) и
  трогают только контейнеры `teamkz-*` с меткой `org.teamkz.managed=true`.
  Другие контейнеры, сети, порты и задачи Планировщика не меняются.

## 3. Требования и файлы

**NAS:** DSM 6.2 с пакетом Docker 20.10.3 или DSM 7.2 с Container Manager;
64-битный процессор x86_64 (amd64) или ARM (aarch64/arm64) — 32-битные ARM и
модели без Docker не подходят; свободно ~1 ГБ на томе; NAS выходит в
интернет (Tailscale, загрузка образа tailscale/tailscale). Возможность
установки зависит от модели NAS: Docker/Container Manager есть не на всех.

**Tailscale:** права администратора tailnet (создать auth key); в tailnet
включены MagicDNS и HTTPS Certificates (уже используются вашими машинами).

**Файлы для загрузки на NAS:**

| Вариант | Что загрузить | Compose |
|---|---|---|
| **A. Готовый образ** (рекомендуется) | `team-kazakhstan-1.0.0-synology.zip` + **один** архив образа для вашего процессора: `team-kazakhstan-1.0.0-linux-amd64.tar` (x86_64) или `...-linux-arm64.tar` (aarch64) в папку `images/` | не нужен |
| **B. Сборка из исходников** | только `team-kazakhstan-1.0.0-synology.zip` (образ соберётся на NAS: нужен интернет, 5–30 минут, ~2 ГБ временного места) | не нужен |
| Альтернатива: Compose | ZIP (+ архив образа или сборка `build: .`) | `compose.yaml`, формат 2.4: docker-compose ≥ 1.28 (DSM 6.2) или Compose v2 / Container Manager (DSM 7.2) |

Архитектура в варианте A выбирается автоматически по `docker version`; если
архива для вашей архитектуры нет, setup.sh собирает образ из исходников
(при `BUILD_FROM_SOURCE=auto`).

## 4. Установка по шагам

Пути ниже — для `/volume1/docker/team-kz`. Другой путь подставьте везде.

### 4.1. Распаковать пакет и проверить NAS

1. File Station → общая папка `docker` → **Создать папку** `team-kz`.
2. Загрузить в неё ZIP → правый клик → **Извлечь → Извлечь сюда**.
   В корне папки окажутся `compose.yaml`, `scripts/`, `.env.example` и др.
3. Вариант A: загрузить архив образа в `team-kz/images/`
   (если архитектура ещё неизвестна — после шага 4).
4. Диагностика (ничего не меняет): Планировщик задач → **Создать →
   Запланированная задача → Пользовательский сценарий**:
   * Общие: Задача `Team KZ diag`, Пользователь **root**, флажок «Включено» снять;
   * Настройки задачи → Выполнить команду:
     `bash /volume1/docker/team-kz/scripts/diag.sh`
   * ОК → выбрать задачу → **Выполнить**.
   * File Station → `team-kz/logs/diag-<время>.txt`: версия DSM, процессор
     (`architecture: x86_64` → amd64, `aarch64` → arm64), версия Docker,
     существующие контейнеры и порты, машины Tailscale, задачи Планировщика.

### 4.2. Ключ Tailscale

<https://login.tailscale.com/admin/settings/keys> → **Generate auth key**:
Reusable — выкл., Ephemeral — выкл., Pre-approved — вкл. (если в tailnet
включено одобрение устройств), Tags — по желанию (`tag:team-kz`, если тег
описан в политике). Скопировать `tskey-auth-…`. Ключ нужен один раз.

### 4.3. Файл настроек `.env`

File Station: `team-kz/.env.example` → правый клик → **Копировать в** ту же
папку под именем `.env` (или скачать, переименовать, загрузить обратно).
Открыть `.env` (пакет «Text Editor» DSM или любой редактор) и заполнить:

| Параметр | Что указать |
|---|---|
| `TS_AUTHKEY` | ключ из 4.2 |
| `TS_HOSTNAME` | имя машины, по умолчанию `team` → `https://team.tail81e59e.ts.net` |
| `DATA_DIR` | постоянные данные, по умолчанию `/volume1/docker/team-kz-data` |
| `BACKUP_DIR` | копии, по умолчанию `/volume1/docker/team-kz-backups` |
| `BACKUP_COPY_DIR` | вторая копия на **другом** устройстве (раздел 9), можно пусто |
| `HTTP_BIND` | `127.0.0.1:8095` (свободный порт; 8080/8088/8443 заняты) или пусто |
| `APP_BASE_URL` | `auto` (имя из Tailscale) |
| `INITIAL_ADMIN_USERNAME`, `INITIAL_ADMIN_PASSWORD` | по желанию: первый администратор без одноразовой ссылки, например `Miras` и ваш пароль (не короче 8 символов) |

Остальное менять не нужно. Окончания строк Windows и комментарии допустимы.
`.env` содержит ключ Tailscale: папка `docker` должна быть доступна только
администраторам. После установки ключ можно удалить из `.env`.

### 4.4. Установка

Планировщик задач → Создать → Запланированная задача → Пользовательский сценарий:

* Общие: `Team KZ setup`, Пользователь **root**, «Включено» — снять;
* Выполнить команду: `bash /volume1/docker/team-kz/scripts/setup.sh`
* (по желанию) «Отправлять сведения о выполнении по эл. почте».

Выбрать задачу → **Выполнить**. Ход — в `team-kz/logs/setup.log`
(File Station → открыть). Обычно 1–3 минуты, сборка из исходников дольше.
Скрипт проверяет Docker, `.env`, порт, создаёт папки с правами
(`team-kz-data/app` — владелец uid 1000, остальное — root, 700),
загружает/собирает образ, запускает Tailscale и приложение, проверяет путь
Tailscale → приложение и создаёт ссылку администратора. Повторный запуск
безопасен.

### 4.5. Администратор

**Вариант 1 — из `.env`.** Если заполнены `INITIAL_ADMIN_USERNAME` и
`INITIAL_ADMIN_PASSWORD`, setup.sh сам создаёт администратора (пароль
передаётся приложению через stdin, в журналы и аргументы команд не
попадает). Вход: имя `Miras` (регистр не важен) и пароль из `.env`.
**Сразу после установки удалите пароль из `.env`** и при желании смените
его: «Мой профиль» → «Сменить пароль». В пакете стандартного пароля нет:
его задаёте вы.

**Вариант 2 — одноразовая ссылка** (если `INITIAL_ADMIN_*` пусты).
В `team-kz/` появится `ADMIN-LINK.txt` с одноразовой ссылкой
`https://team.tail81e59e.ts.net/setup#token=…` (действует 60 минут, в
журналы не пишется). Откройте её на устройстве с Tailscale, задайте имя,
логин и пароль администратора (например, Мирас). Стандартного пароля нет.
Удалите файл после использования (он удаляется и автоматически).
Если ссылка истекла: задача с командой
`bash /volume1/docker/team-kz/scripts/admin-link.sh` → Выполнить.

## 5. Задачи Планировщика

Все задачи: **Пользовательский сценарий** (User-defined script), пользователь **root**, рабочая
директория не нужна (скрипты находят свою папку сами). Каждая операция
берёт блокировку `state/ops.lock`: повторный или одновременный запуск
не выполнит действие дважды (сообщение «another operation is running»).

**Постоянные (включены):**

| Задача | Тип и расписание | Команда |
|---|---|---|
| Team KZ boot | Создать → **Инициируемая задача** (Triggered Task) → Событие «**Загрузка**» (Boot-up) | `bash /volume1/docker/team-kz/scripts/start.sh --boot` |
| Team KZ watchdog | Запланированная (Scheduled Task): ежедневно, «Частота» **каждые 15 минут** (Repeat every 15 minutes), первый запуск 00:00, последний 23:45 | `bash /volume1/docker/team-kz/scripts/start.sh --check` |
| Team KZ backup | Запланированная (Scheduled Task): ежедневно, 03:15 | `bash /volume1/docker/team-kz/scripts/backup.sh` |

* Задача «boot» **обязательна**. При выключении DSM останавливает все
  контейнеры, а после включения запускает их сам, но не по порядку:
  приложение стартует раньше своего Tailscale-контейнера и остаётся
  выключенным (`cannot join network of a non running container` в
  `/var/log/messages`; так проверено на реальном NAS с расписанием питания).
  «boot» ждёт Docker до 10 минут и запускает оба контейнера в нужном порядке.
  Если вы остановили справочник через stop.sh, после перезагрузки он **не**
  запускается, пока не выполнен start.sh.
* «watchdog» молчит, если всё в порядке; при сбое (контейнер упал, после
  перезапуска Tailscale-контейнера приложение недоступно) чинит и пишет в
  `logs/watchdog.log`. Также удаляет старый `ADMIN-LINK.txt`.

**Разовые (выключены, запуск кнопкой «Выполнить»):**

| Задача | Команда |
|---|---|
| Team KZ setup | `bash /volume1/docker/team-kz/scripts/setup.sh` |
| Team KZ start | `bash /volume1/docker/team-kz/scripts/start.sh` |
| Team KZ stop | `bash /volume1/docker/team-kz/scripts/stop.sh` |
| Team KZ update | `bash /volume1/docker/team-kz/scripts/update.sh` |
| Team KZ rollback | `bash /volume1/docker/team-kz/scripts/rollback.sh --yes` |
| Team KZ restore | `bash /volume1/docker/team-kz/scripts/restore.sh --latest --yes-overwrite` (или путь к архиву) |
| Team KZ admin link | `bash /volume1/docker/team-kz/scripts/admin-link.sh` (`--reset miras` — новый пароль) |
| Team KZ funnel | `bash /volume1/docker/team-kz/scripts/funnel.sh on` — открыть по ссылке без Tailscale (`off` — только tailnet, `status`) |
| Team KZ diag | `bash /volume1/docker/team-kz/scripts/diag.sh` |
| Team KZ demo | `bash /volume1/docker/team-kz/scripts/demo-data.sh --yes` (`--remove` — удалить) |

Журналы всех задач — `team-kz/logs/<задача>.log` (ограничены 1 МБ).
По SSH те же команды выполняются через `sudo bash …`.

## 6. Первые шаги в приложении

1. Администратор (Мирас): **Admin → Companies and teams** — Algoritmi и
   Green Spark уже есть; добавьте команды и другие компании.
2. **Director → Add employee** (по-русски «Директор → Добавить сотрудника») —
   добавьте Динару как сотрудника; **Admin → Users and access → Invite a
   person**: роль Director (Директор), «Link to employee profile» — Динара →
   ссылка → отправьте ей лично.
3. Директор добавляет сотрудников (официальная должность, компания,
   команда, доступность для Algoritmi) и создаёт каждому личную ссылку
   (**Create invitation → Copy link**), отправляет в мессенджере.
   Таблица показывает заполненность профилей и у кого нет фото.
   Неподходящее фото директор может удалить (Edit → Remove photo);
   новое фото делает только сам сотрудник камерой.
4. Сотрудник открывает ссылку на телефоне, задаёт логин и пароль, попадает
   в «My profile»: заполняет профессию, текущие задачи, языки, контакты и
   делает селфи. Официальные поля он видит, но изменить не может.
5. Гостям из Италии и Швейцарии — роль **Visitor** (только просмотр):
   Admin → Invite a person → Role: Visitor.
6. Демонстрационные данные — только явно: задача «Team KZ demo»;
   удаление — Admin → Backups and export → Remove demo data.

Роли: **Administrator** — всё, включая пользователей, роли, компании,
журнал, копии и экспорт; **Director (Директор)** — добавление и
редактирование сотрудников, официальные поля, приглашения сотрудникам,
контроль заполненности (во внутренних данных роль называется
`coordinator`); **Employee** — только свой
профиль без официальных полей; **Visitor** — только просмотр. Права
проверяются на сервере для каждого запроса.

## 7. HTTPS и камера

Браузеры дают доступ к камере только «безопасным» страницам (https:// или
localhost). Само подключение Tailscale шифрует трафик, но адрес вида
`http://100.x.y.z` или `http://nas:8095` для браузера не безопасен — камера не
включится. Поэтому справочник открывается только через **Tailscale Serve**:
`https://team.tail81e59e.ts.net` с настоящим сертификатом Let's Encrypt,
который Tailscale получает и продлевает сам (нужен параметр tailnet
«HTTPS Certificates»). Funnel (публикация в интернет) не включается.

Свой домен вида `https://team.company.kz` — режим `DEPLOY_MODE=proxy`:
HTTPS делает обратный прокси DSM (Панель управления → Портал входа →
Дополнительно → Обратный прокси, источник `https://team.company.kz:443`,
назначение `http://127.0.0.1:8095`) с сертификатом для этого имени
(например, Let's Encrypt через DNS-проверку), во внутреннем DNS
`team.company.kz` → IP NAS. В `.env`: `DEPLOY_MODE=proxy`,
`APP_BASE_URL=https://team.company.kz`, `HTTP_BIND=127.0.0.1:8095`,
`TRUST_PROXY=auto`. Портов в интернет это не открывает; на DSM 6.2 обратный
прокси работает на веб-сервере DSM без обновлений безопасности — учитывайте.

## 8. Доступ людей

Справочник доступен только устройствам в вашем tailnet. Каждому человеку
нужно приложение Tailscale (iOS/Android, бесплатно) и доступ:
* сотрудникам группы — приглашение в tailnet (admin → Users → Invite users);
* внешним гостям — **Machines → team → Share**: гость видит только эту машину;
* по желанию — правило в политике tailnet, чтобы к `team` подключались
  только нужные группы.

Затем — короткая ссылка `https://team.tail81e59e.ts.net` и вход по логину.
Ярлык на телефоне: iPhone — Safari → «Поделиться» → «На экран „Домой“»;
Android — Chrome → ⋮ → «Добавить на главный экран». Справочник открывается
одним касанием, как приложение, без установки из магазина.
Без Tailscale на устройстве сайт не откроется: это режим по умолчанию.

**Открывать без Tailscale (Tailscale Funnel).** Так же, как опубликованы
другие сайты этого NAS (algoritmi, green-spark, kzit): задача
`bash …/scripts/funnel.sh on` записывает `TS_FUNNEL=true` в `.env` и
перезапускает Tailscale-контейнер с публикацией через Funnel. Ссылка
открывается на любом устройстве без установки приложения — удобно для
гостей. Порты на NAS и роутере не открываются: трафик идёт через Tailscale.
Публичной становится страница входа; все данные — только после входа
(ограничение попыток, CSRF, HttpOnly-cookie). **Всем учётным записям —
длинные пароли.** Имя в интернете появляется в течение ~10 минут.
Выключить: `funnel.sh off`. Нужен атрибут `funnel` у машины в политике
tailnet (в политике по умолчанию он есть для участников).

## 9. Резервные копии и восстановление

**Что копируется:** база SQLite (снимок `VACUUM INTO` — согласованная копия
работающей WAL-базы, без остановки приложения) и ровно те фотографии, на
которые ссылается снимок; `manifest.json` с SHA-256 каждого файла.
Не копируется состояние Tailscale (на новом NAS — новый auth key).

**Как:** задача «Team KZ backup» ежедневно → `BACKUP_DIR/team-kz-backup-
<дата>-<время>-scheduled.tar.gz` + `.sha256`; проверка gzip, манифеста и
суммы; хранение `BACKUP_RETENTION_DAYS` (30) дней, но не меньше
`BACKUP_MIN_KEEP` (7) последних. Последняя копия видна в Admin → Backups.
Из панели администратора можно создать и скачать копию вручную.

**Копия на том же NAS не защищает от потери NAS.** Варианты без облака:
* `BACKUP_COPY_DIR` на USB-диске: `/volumeUSB1/usbshare/team-kz-backups`;
* папка другого NAS/сервера, подключённая на этом NAS: File Station →
  Инструменты → **Подключить удалённую папку** (CIFS/NFS), путь в
  `BACKUP_COPY_DIR`; если она недоступна, задача завершится с кодом 2;
* Hyper Backup → задача на другой Synology/rsync-сервер для папки
  `team-kz-backups` (и `team-kz-data` при желании).

**Восстановление** (на этой же или чистой установке):
1. Чистый NAS: шаги 4.1–4.4 (setup.sh), ссылку администратора не использовать.
2. Положить архив (и `.sha256`) в `BACKUP_DIR`.
3. Задача: `bash /volume1/docker/team-kz/scripts/restore.sh --latest`
   (на установке с данными добавить `--yes-overwrite`).
4. Скрипт проверит архив (gzip, SHA-256, манифест, суммы файлов,
   целостность SQLite, версию схемы), сделает копию текущих данных,
   остановит приложение, восстановит, запустит и проверит. Старые файлы
   остаются в `team-kz-data/app/pre-restore-<время>/`.
5. Вход — прежними логинами из копии.

## 10. Обновление и откат

**Обновление:**
1. File Station: загрузить новый ZIP в `team-kz` → Извлечь сюда →
   **заменить** файлы (`.env`, `logs/`, `state/` не входят в ZIP и остаются;
   данные лежат в `team-kz-data`).
2. Положить новый архив образа в `images/` (или собрать из исходников).
3. Задача «Team KZ update» → Выполнить.
   Порядок: образ готов → **копия базы до миграций** →
   приложение пересоздаётся новым образом → миграции применяются
   автоматически при старте (в одной транзакции, с защитой от
   одновременного запуска) → проверка. Задача start.sh версию не меняет.

**Откат:** миграции меняют схему только вперёд, и старая версия не
работает с более новой схемой (откажется стартовать с понятным
сообщением). Поэтому откат = прежний образ **плюс** копия, сделанная
update.sh перед миграциями: задача `rollback.sh --yes`. Изменения после
обновления теряются; они сохраняются в копии `pre-rollback` (её может
прочитать только новая версия). Предыдущий образ хранится до следующего
обновления.

## 12. Безопасность

* **Сеть:** установка не открывает портов в интернет; Funnel включается
  только явно (`TS_FUNNEL=true` / `funnel.sh on`); проброс портов на роутере
  не нужен. DSM администрируйте только через
  Tailscale/VPN (`https://<имя NAS>.<tailnet>.ts.net:5001` или из офисной
  сети); порты DSM (5000/5001, 80/443) в интернет не открывайте.
* Нет публичной регистрации и стандартных паролей; первый администратор —
  из `INITIAL_ADMIN_*` в `.env` (пароль задаёте вы) или одноразовой ссылкой
  из Планировщика (или `create-admin` по SSH). Создать администратора через
  веб-интерфейс может только существующий администратор; добавлять
  сотрудников — только администраторы и директоры.
* Пароли не короче 8 символов (минимум по NIST SP 800-63B), без имени
  пользователя внутри и не из списка самых частых.
* Пароли — scrypt (N=2¹⁵, r=8, p=3, соль); серверные сессии в базе
  (хранится SHA-256 токена), cookie `HttpOnly`, `SameSite=Lax`, `Secure` и
  префикс `__Host-` на HTTPS; срок 7 дней, бездействие 48 часов.
* Ограничение попыток входа (8 неудачных на логин и 30 на адрес за 15 мин).
* Приглашения и сброс пароля: 256-битный случайный токен в части `#…`
  ссылки (не попадает в журналы и Referer), в базе — только SHA-256,
  срок действия, одноразовость, отзыв и перевыпуск; до активации ссылка
  показывает только имя адресата.
* CSRF: токен сессии в заголовке для всех изменяющих запросов, проверка
  `Origin`/`Sec-Fetch-Site`; CORS не выдаётся никому; проверка `Host`.
* CSP `default-src 'self'` без inline-скриптов, внешних шрифтов и CDN;
  `frame-ancestors 'none'`, `nosniff`, `Referrer-Policy: no-referrer`, HSTS.
* Проверка всех входных данных (zod), только параметризованные SQL-запросы,
  ограничения размеров запросов (64 КБ JSON, 3 МБ фото).
* Фото: только JPEG, проверка размеров до декодирования, декодирование и
  повторное кодирование на сервере в 512×512 без EXIF/GPS; выдача только
  через авторизованный адрес `/api/photos/<случайный id>.jpg`.
* Журнал действий: входы, приглашения, роли, официальные поля (было/стало),
  деактивация, копии, экспорт; без паролей и токенов; для личных полей —
  только названия полей.
* Деактивация сотрудника/пользователя отзывает сессии и ссылки.
* Контейнер: uid 1000, read-only, `--cap-drop ALL`, `no-new-privileges`,
  лимиты памяти и процессов, журнал Docker 3×10 МБ.

**Где хранятся данные.** База (SQLite `team-kz.sqlite`) и фотографии —
только на NAS в `/volume1/docker/team-kz-data/app` (у контейнера — `/data`).
В браузер попадает только код страницы (JS/CSS без данных и без исходных
карт) и ответы API на то, что пользователю можно видеть после входа. Браузер
хранит лишь выбранный язык (`localStorage`) и cookie сессии с флагами
HttpOnly, Secure, `__Host-` (JavaScript её прочитать не может). Через F12
нельзя скачать базу, `.env`, исходники, миграции или копии: такие адреса
отвечают 403/404 или пустой страницей приложения. Проверка с любого
компьютера в tailnet:
`CHECK_USER=miras CHECK_PASSWORD=… node tools/check-exposure.mjs https://team.tail81e59e.ts.net`

## 13. Ограничения

* **Не проверено на вашем NAS**: у меня не было доступа к NAS и Docker на
  этом компьютере не работает. Скрипты проверены на имитации Docker
  (раздел 15), образы собраны без Docker и проверены по структуре.
  Требует проверки на месте: запуск на ядре DSM и Docker 20.10,
  Tailscale-контейнер, сертификат, камера на iPhone/Android.
* Веб-страница может предложить только съёмку камерой, но **не может
  доказать**, что фото снято камерой: технически грамотный пользователь
  может подменить запрос. Сервер всё равно принимает только JPEG и
  перекодирует его.
* Для доступа нужен Tailscale на каждом устройстве (раздел 8).
* Один процесс приложения; ограничение попыток входа хранится в памяти и
  сбрасывается при перезапуске.
* Оргструктура (подчинение) не строится: данных о руководителях нет.

## 14. Вариант с Docker Compose

Если удобнее Compose (Container Manager → Проект на DSM 7.2 или
`docker-compose` 1.28+): `compose.yaml` в корне пакета (Tailscale-контейнер
+ приложение), `compose.proxy.yaml` — без Tailscale, за своим обратным
прокси. Перед первым `up`: `.env` с явным `APP_BASE_URL=https://…`
(значение `auto` работает только в скриптах), папки — `sudo bash
scripts/setup.sh --prepare-only`, образ — `docker load -i images/…tar` или
`build: .`. Используйте **либо** скрипты, **либо** Compose: имена контейнеров
одинаковые.

## 15. Разработка и проверки

```
npm ci                 # зависимости строго по package-lock.json
npm run typecheck      # TypeScript (сервер и клиент)
npm run build          # dist/server + dist/web
npm test               # 22 теста: API на настоящем процессе сервера и настройки
bash tools/nas-sim/run.sh [images/…tar]   # скрипты NAS на имитации docker
python -I tools/build-image.py --stage <app> --version 1.0.0 --out release
```
Локально: `npm run build && npm start` (http://localhost:8080; первая
ссылка администратора — `npm run cli -- setup-link`), разработка
интерфейса — `npm run dev:web`. Что проверено — `BUILD_INFO.md`.

**Почему Alpine:** профиль seccomp старого Docker 20.10 на DSM 6.2 ломает
образы на новом glibc (системный вызов clone3); Node.js на Alpine (musl) этим
не страдает. Нативных модулей нет (SQLite встроен в Node 24, фото — на
чистом JavaScript), поэтому один и тот же код работает на amd64 и arm64.
